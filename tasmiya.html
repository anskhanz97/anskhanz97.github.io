Purpose and my role

A multi-division business website and management system with profile/service content, reviews, customer inquiries, CRM operations and payment workflows. My contribution spans the administration interface, backend behavior and provider integrations.

Operational workflows and collaboration

Website and CMS

Multi-division business content, team profiles, service offerings, testimonials/reviews, role-based administration and responsive editing interfaces.

CRM and follow-ups

Department/person inquiry routing, lead ownership, duplicate and returning-inquiry handling, activity history, calendar follow-ups, conversion, reopening and access-controlled collaboration.

Customer communications

Meta WhatsApp inbound text and authorized replies, signed callbacks and delivery status; per-user in-app notices, SMTP follow-up digests, scheduled reminders, retries and delivery history.

Reviews and payments

Google Places API business ratings, reviews and attribution; Stripe PaymentIntent creation/confirmation; external-payment references and private proof submission for staff review.

Cloud APIs and identity

Google Drive API and Google Picker API

Google OAuth requests drive.file access. Google Picker selects images; Drive v3 retrieves image bytes and checks metadata. The flow imports selected files into normal upload controls, validates content and verifies configuration.

OneDrive and Microsoft Graph REST API

MSAL manages Microsoft sign-in and Files.Read access. Microsoft Graph v1.0 lists files/folders with pagination, retrieves selected image metadata/download URLs and imports validated image files. This is a REST integration.

Architecture and reliability

Laravel policies and transactional CRM workflows protect ownership and case state. Immutable inquiry/activity history and optimistic versions support competing edits. Provider configuration belongs in administration; credential handling, signed webhooks, provider IDs, retries and delivery evidence support recoverable integrations.

Interface design

I built and refined the public site, profile/content editor and CRM workspace: responsive layouts, multi-division presentation, clear image-source actions, Google/OneDrive picker states, searchable controls, activity history, notifications and follow-up management.

Implementation and verification evidence

The code contains Google OAuth/Picker and Drive v3 requests, MSAL and Microsoft Graph REST requests, the Google Places provider call, Stripe PaymentIntent flows and WhatsApp/SMTP services. CRM verification records cover routing, ownership, duplicates, stale writes, conversion/reopening, callbacks and notification failures. Live provider delivery is not inferred from local tests.

Release status and responsibilities

Website/CMS, CRM and integration implementations are present. Provider credentials, account approvals and live acceptance are required for their respective live services.
