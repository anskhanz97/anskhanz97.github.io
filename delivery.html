Delivery Driver

Purpose and my role

An independently deployable delivery operations service connected to Retail Cloud and till workflows. I build the backend/owner portal and integration contracts, coordinating with the Flutter mobile and C# desktop developers who implement their client applications.

Operational workflows and collaboration

Retail and desktop integration

Tenant/store/owner provisioning, driver eligibility and credentials, assignment ingestion, versioned source events, outboxes, signed callbacks and Retail delivery projections.

Flutter mobile integration

Bearer authentication, device registration/revocation, token refresh support, assigned orders, lifecycle transitions, offline command receipts, private avatars, custody/proof records and wallet reconciliation.

Cash and operational control

Atomic cash-on-delivery collection, immutable wallet/ledger effects, till floats and partial/full handovers, pending physical receipts, recovery/checkpoints and owner reporting.

Team enablement

Shared Postman collection, endpoint examples, backend/Flutter responsibility matrix, till contracts and joint debugging of registration, order events, wallet state and notification setup.

Firebase, APNs and push telemetry

Firebase Cloud Messaging

The backend signs service-account assertions, obtains/caches an OAuth access token and sends authenticated FCM HTTP v1 messages. Device tokens are encrypted; notification outboxes, per-device results, queue retries and scheduled redrive handle dispatch and recovery.

Android and Apple Push Notification service

FCM messages include Android priority and iOS/APNs alert/background configuration. Device registration records permission/platform state. Flutter handles its native Firebase setup and platform notification handlers; backend and client responsibilities are coordinated.

Receipt telemetry

Mobile APIs accept received/displayed/opened notification stages with idempotency and clock-quality checks. Metrics expose device readiness, acceptance/receipt funnels and p50/p95 dispatch and device-receipt latency. FCM acceptance is recorded separately from actual phone delivery.

Architecture and reliability

Laravel APIs own authorization, immutable lifecycle history and transactional wallet/cash effects. Version checks and replay receipts reconcile desktop/source, cloud and offline mobile operations. Background notification/integration/export workers and the scheduler provide retries and recovery, with structured operational logs.

Interface design

The Vue owner portal supports Overview, Orders, Drivers, Customers, Cash ledger, Reports and Settings/readiness. My work includes responsive navigation, auth/session behavior, consistent controls, deep links, reporting/export flows and notification readiness/telemetry views.

Implementation and verification evidence

Documented backend and Postman verification covers driver APIs, lifecycle transitions, COD/wallet reconciliation, retries, tenancy, FCM message shape/authentication, device registration and receipt telemetry. The Firebase setup chat also records coordination with the Flutter developer around Android/iOS project configuration, registration requests and token lifecycle.

Release status and responsibilities

Backend/portal and notification infrastructure are implemented, with Firebase setup coordinated for the deployed service. Real Android/iOS background delivery and latency sign-off require the running mobile builds, provider configuration and device measurements.
